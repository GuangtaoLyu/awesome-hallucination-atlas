## README 嵌套折叠"默认展开"二次修复（真正根因）
- **用户二次反馈"还是不对"** —— 去掉转义后仍展开。真正根因是**嵌套 `<details>` 的相邻边界缺空行**：gen_list 上一年组 `</details>\n` 紧接下一年组 `<details>\n`（仅换行无空行），CommonMark/GitHub 把这两行合并成**一个 HTML block**，嵌套解析报废 → 年份子组全摊开。模型组之间同理。
- **修复**：重写 `gen_list`，改用"块列表 + 块间 `\n\n` 双换行"，并在每个年份子组的 `</details>` 之后、下一个 `<details>` 之前强制插空行（模型组闭合后同样留空行）。awk 校验 `</details>` 紧接 `<details>`（无空行）的相邻对 = 0。
- **经验（可复用）**：GitHub markdown 渲染嵌套 `<details>` 的硬约束——任何 `</details>` 与下一个 `<details>` 之间必须有**空行**，否则被合并成单 HTML block 导致永久展开。这比"去掉反斜杠转义"更深一层。已提交 `1588b7a`（含 gen_readme.py 脚本修复，避免流水线重跑重现）。

## README 开头徽章 / 标题渲染修复（双 bug 叠加）
- **用户截图反馈**：徽章 `<img src="...">` 在渲染器里直接以**原始 HTML 文本**露出，没显示成图片。
- **根因**（README.md 头部，共 2 处）：
  1. **每个标签都被反斜杠转义**：`\<p align='center'>`、`\<img src=...>`、`\</p>` —— CommonMark/Markup 解析后这些就是字面 `<img ...>` 文本，不会被当成 HTML 块渲染。
  2. **`src` 里的 URL 外面又包了一层尖括号**：`src='<https://img.shields.io/...>'` —— 即便去掉反斜杠也是非法 HTML，浏览器不会加载图片。
- 标题第 1 行同病：`[[Awesome](...)\](<https://awesome.re>)` 含 `\]` 转义 + `<URL>` 尖括号。
- **修复**：徽章改用**标准 markdown 图片语法** `![alt](url)`（GitHub/IDE 预览/WorkBuddy 等所有 CommonMark 渲染器都识别），标题改为 `[![Awesome](badge.svg)](awesome.re)` 嵌套图片链接。`update_badges` 的正则仍作用于 URL 段，与外层包裹语法无关——已验证 `Papers-1893 / Abstract--based-1391 / Last%20Update-2026-07` 与 `papers.json` 的 1893 / 1391 / 当前月一致。提交 `72dc0dc`。
